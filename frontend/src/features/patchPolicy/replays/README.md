# Patch-policy reference replays

Each `.json` here is one whole output of LoonVD's patch-policy replay, schema 2, copied byte for
byte. LoonInspect draws these files and computes nothing in them (#614, first slice).

A schema-2 replay names its own release dates: its `timeline` block says which public release
record the dates come from, where that record is, when it was fetched, its SHA-256, and what one of
its dates means. The page prints that block as it stands under *Evidence › Release dates*. Every
replay counts each CVE from its NVD publication date (the file's `clocks.published`), and the page
says so under *Evidence › CVE clock*.

`wireshark-2026-10-02.json` is a schema-1 file that is still in this directory and is not
indexed: this build refuses schema 1, so the page never loads it, and it leaves when the schema-2
files arrive.

One row per file, and one file per row: `replay.test.ts` fails when an indexed file has no row
here, or a row whose SHA-256 is not the file's. The columns:

- **Release dates from** is the file's `timeline.name`, with `timeline.url` as its link.
- **What a date means** is the file's `timeline.clock`, as the file words it.
- **CVE clock** is NVD's publication date for every schema-2 replay.
- **Generated by** is the LoonVD-Internal commit, and the command, that wrote the file.
- **Bytes** and **SHA-256** are the file's, as copied here.

These are reference analyses of a hypothetical device. They are not a tenant's exposure, they
are never stored as a tenant metric, and no inventory is read to draw them. What every number
means, and which definitions are ruled, is `docs/PATCH-POLICY-REPLAY.md` in LoonVD-Internal; the
definitions also ride in each file as `definitions` and `clocks`, and the page prints them from
there.

## Adding or replacing one

1. Copy the new output here without editing it. The name is `<app>-<window end>.json`.
2. Add or update its entry in `../replayIndex.ts`: the app's name, its bundle IDs, the file's
   name, and a `load` that imports that file.
3. Add or update its row in the table above, from the file's own `timeline` block and its bytes.
4. Run `npm test`. `replay.test.ts` reads every indexed file through the same check the page
   uses, so a file of another `kind` or `schema`, one that names no release-date source, or one
   whose totals disagree fails there and not in front of a reader. It also fails a file that
   carries a Jamf or Fleet key, or names either as its source.

This directory is how the files reach the page for this slice only. The distribution from
LoonVD through LoonSupport is not designed here.
