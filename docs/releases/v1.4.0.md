# LoonInspect v1.4.0: release notes

Status: **draft for the v1.4.0 tag** (#946). Everything below the first rule becomes the
release body. The lines marked *(filled in at the tag)* are completed before publication.

---

LoonInspect v1.4.0 adds Jamf-to-Fleet migration planning to the Fleet catalog, behind its
flag, and lists Posture › Patch policy for everyone, walking LoonSec's patch-policy data when an
organization holds it. It also moves Patch Plans into the main navigation, filters observed
changes by field and time, shows AI activity and workload health, and gives the Mac app Back and
Forward controls and a clean-uninstall helper.

## What ships

- **Jamf-to-Fleet migration planning** (#893), behind `fleet_maintained_apps`, which stays off by
  default. Devices › Applications › Fleet catalog gains **Migration review**: each app Jamf
  inventoried on the Macs the device filter selects, with its coverage in both catalogs, its
  patch-rule verdict and its installed builds' vulnerability evidence, sorted by patch priority.
  An app's or a Fleet title's own page shows its builds and Macs, observed upgrades and release
  history, compares the Macs against a target version, and describes how a Fleet pilot would
  start. An optional AI briefing sends a saved provider at most seven aggregate counts, never an
  app, version or Mac, and only when **Generate briefing** is pressed. Fleet's version history
  gains version search, manifests and a release cadence, and a catalog check now says whether it
  read the catalog whole or in part, and why. Nothing here deploys anything.
- **Posture › Patch policy** (#614), now listed for every account that can read applications.
  It is a reference analysis of one hypothetical Mac, walked day by day under a patch-policy
  slider, not this organization's exposure. Once LoonSec's patch-policy data reaches an
  organization through the data-sharing exchange (or, air-gapped, through
  `PATCH_POLICY_FEED_FILE`), the page walks it, dating each release from the public record, this
  instance's copy of Jamf's patch catalog, or its Fleet version history. Until then it draws four
  reference replays that ship with the build. The walk reads no inventory and stores nothing.
- **Patch Plans in the main navigation** (#883), with its own `/patch-plans` page. Planning
  from an installed application still works, and saved-plan links redirect.
- **Observed changes by field and time** (#882): which devices changed an exact field to a value
  within a window, with distinct-device totals across the whole filtered result.
- **AI activity and workload health** (#886), linked from Overview and Settings: past calls by
  service, purpose, model and outcome, and a live workload panel.
- **The Mac app** gains Back and Forward controls and a title bar that follows the app's
  appearance (#888), and a clean-uninstall helper in the app and at the disk image's root that
  previews what it removes and asks for a backup decision and a typed confirmation (#869).
- **Smaller fixes.** The Catalog tab has the **Refresh** button the runbook names (#933). A
  patch-rule verdict's date follows the page's language (#939). A title Fleet's catalog lists
  twice is held, not guessed (#928). A refused corpus selection answers with its own sentence
  (#934). An administrator created with a private-domain address can sign in (#880).

## Security fixes

- Database failures no longer carry statement text or bound values into diagnostics (#876).
- Outbound provider failures no longer store or log upstream response bodies or
  credential-bearing exception text (#877).
- Production images hold only runtime inputs: application code, migrations and package
  metadata, not tests or fixtures (#878).
- Patch-plan provenance withholds source addresses that embed credentials or query values (#879).
- Update-provider failures are classified safely instead of being reported as a database
  problem (#881).
- The Zod used by React Hooks linting is 4.6.7 (GHSA-mrhx-c7xc-m3w5, #884).

Snowflake live inventory export (#848) is not part of this release.

## Upgrade and recovery

Back up the database, or stop the Mac app and keep its complete Application Support folder,
before upgrading. Three migration revisions since v1.3.0 add service identity and lifecycle
facts to AI usage, and two global tables for LoonSec's patch-policy data and the last attempt to
receive it. All three are additive.

**Returning to v1.3.0 needs no restore.** The schema's minimum readable release stays v1.3.0,
so v1.3.0 opens an upgraded database: swap the image back, or reinstall LoonInspect 1.3.0.
Releases before v1.3.0 still need their pre-upgrade backup.

## Known limitations

- The Mac app is for Apple silicon and runs its services while open. Updating replaces the
  bundle; there is no in-app updater.
- Fleet migration planning ships off. Fleet's catalog files are under Fleet's `ee/` licence,
  which says production use needs a Fleet subscription. A title in Fleet's catalog is no
  evidence that any policy is deployed.
- Posture › Patch policy is a reference analysis of a hypothetical Mac, not this organization's
  exposure, and shows the bundled replays until LoonSec's data reaches the organization.
- Findings are exposures per assessed device and build, not unique CVEs. Unknown or stale
  assessments do not count as zero.
- Jamf macOS inventory remains the supported MDM scope. Snowflake delivery is not in this
  release.
- Existing limitations in KNOWN_ISSUES.md remain. Preview feature defaults are unchanged.
