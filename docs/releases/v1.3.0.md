# LoonInspect v1.3.0: release notes

Status: **draft for the v1.3.0 tag** (#867). Everything below the first rule becomes the
release body. Validation and artifact lines marked at the tag are completed before publication.

---

LoonInspect v1.3.0 brings patch planning to Installed Applications, adds nested device and
vulnerability scopes, and exposes inventory evidence to Codex and Claude through MCP.
It also adds macOS upgrade eligibility, optional recent Jamf polling, AI usage history,
and selection of compatible models already loaded on Ollama.

## What ships

- **Installed application patch plans and auditor PDFs** (#860, #866). Build from an
  installed application, retain Jamf/Fleet/Installomator evidence and provenance, review
  a pilot and recovery plan, investigate in the background, and export a saved revision.
  An AI review is optional; a plan does not execute a deployment or attest to completion.
- **Application and device scoping** (#866). Filter by name, severity and KEV; see uncapped
  known findings, average per assessed device and assessment coverage. Nested AND/OR
  brackets support connection, groups, EAs, activity dates and enrollment state.
  Managed and Supervised are independent. Smart group style implicitly requires managed
  devices; Advanced search offers Managed explicitly. EA comparisons include literal
  substrings and PostgreSQL regex. Calendar comparisons exclude the selected UTC day.
  AI proposes reviewable JSON, with explicit Load and Apply steps.
- **MCP for Codex and Claude** (#858, #864). Use scoped, revocable credentials over HTTP
  or the native Mac stdio bridge for inventory, posture, runs and evidence. Live Claude
  Code reads passed on both transports; Claude Desktop UI and live Jamf refresh actions
  were not part of that validation.
- **macOS adoption and hardware eligibility** (#853). Explore observed version history
  and dated hardware evidence for an upgrade target. Missing observations stay visible.
- **Recent Jamf activity polling** (#854). Opt into 15-minute collection between full
  crawls, with persisted windows, recovery and daily coverage reconciliation.
- **AI usage and capacity** (#855). Inspect reported tokens, processing time, completions,
  queue waits and expirations by feature, provider and model.
- **Loaded Ollama models** (#856). Keep a pinned model or select a compatible model
  already loaded on the configured endpoint, recording requested and reported models.

Snowflake live inventory export (#848) is scheduled for **v1.4.0**, per the release scope
change on 2026-11-23. The older Fleet migration draft (#857) remains unmerged. Neither is
part of this release.

## Upgrade and recovery

Back up the database or stop the Mac app and retain its complete Application Support
folder before upgrading. Seven migration revisions since v1.2.0 add recent-activity
provenance, AI usage counters, model-selection configuration, catalog reconciliation,
patch plans and cross-organization token metadata, and join the migration branches.

**Returning to the published v1.2.0 requires restoring a pre-upgrade backup.** Recent
activity schedules raise the minimum readable release to v1.3.0; v1.2.0 cannot read those
collection kinds. Do not point the old release at the upgraded database. Existing local
feature-preview builds may already have applied these migrations despite their older
version label.

## Known limitations

- The Mac app is for Apple silicon and runs its services while open. Updating replaces
  the bundle; there is no in-app updater.
- Findings are exposures per assessed device/build, not unique CVEs. Unknown or stale
  assessments do not contribute zeroes. Regex syntax can differ from Jamf's engine.
- Plans and evidence reports require operator review. AI cannot create Jamf groups or
  deploy patches through this planning workflow. Background plan investigations are
  bounded and reported interrupted after a process restart.
- Jamf macOS inventory remains the supported MDM scope. Snowflake delivery is deferred.
- Existing limitations in KNOWN_ISSUES.md remain. Preview feature defaults are unchanged.
